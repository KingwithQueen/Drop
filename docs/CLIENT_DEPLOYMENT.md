# Drop 1.0.2 客户端

本包包含 Drop 托盘客户端、所需运行 DLL、第三方许可和文件校验清单。将整个文件夹解压到你选择的目录，保留 DLL。需要与包架构对应的 Microsoft Visual C++ v145 运行时。

## 可选的目录与快捷方式配置

客户端首次启动会自动初始化，无需在本机创建账号。包内 Setup-Drop.ps1 可以帮助指定程序目录和数据根目录，并生成数据根目录下的 Drop.lnk 快捷方式：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'E:\Program Files\Drop\Setup-Drop.ps1' -ProgramDirectory 'E:\Program Files\Drop' -DataDirectory 'E:\ProgramData\DropClientData' -ServerUrl 'https://dropserver.jsnowly.win:8443' -Login 'Jsnowly' -Launch
```

只设置两个目录即可，实际客户端缓存自动放在数据根目录的 client 子目录。ServerUrl、Login 均可省略后在 Drop 的「配置与账号」窗口填写；账号保留大小写，密码只在程序内输入。-Launch 配置完成后启动客户端，省略则双击生成的 Drop.lnk。-Preview 只显示路径，不写文件。脚本保留已有 ui.json 和登录数据，不覆盖不同目标的快捷方式，不修改自启动或系统代理，也不在桌面、AppData 创建文件。

使用日常登录的 Windows 用户运行客户端脚本，数据根目录应是该用户可写的独立目录；服务器数据根目录受管理员/SYSTEM 保护，不能同时拿来存放客户端缓存。程序目录只读取，不要求为创建快捷方式写入 Program Files。

## 在另一台电脑登录

账号由中央服务器管理员创建。取得服务器地址、Drop 账号和密码后启动 drop.exe，点击工具栏「配置与账号…」或菜单「工具 → 配置与账号」，在配置窗口填入服务器完整地址和账号凭据。账号支持大小写英文字母，登录时使用创建时的相同大小写；同一账号可以在多台电脑登录，接收自己的消息和附件。Google 授权由中央服务器管理。

如果服务器使用公开受信任证书，地址填写 `https://证书覆盖的服务器域名:8443`，私有 CA 一栏留空。域名必须在本机解析到服务器实际地址。若服务器采用 HTTP/PAKE，填写管理员提供的 `http://服务器地址:8080`；客户端根据地址选择相应连接方式。

客户端遵循 Windows 系统代理。访问局域网服务器时，在系统代理的“不使用代理／例外”列表加入服务器域名，例如 `dropserver.jsnowly.win`。ping 成功不代表应用连接成功；如果服务器接口直连正常而 Drop 测试失败，核对系统代理和私有 CA 设置。仅在代理软件内配置规则时，也应核对该域名实际走直连路径。

客户端本地数据默认位于 drop.exe 旁的 `Data\Drop`。需要指定目录时，在本机 PowerShell 执行，按实际磁盘位置替换两个路径：

```powershell
& 'E:\Program Files\Drop\drop.exe' --ui-root 'E:\ProgramData\DropData\client'
```

快捷方式的“目标”也可填写：

```text
"E:\Program Files\Drop\drop.exe" --ui-root "E:\ProgramData\DropData\client"
```

每台电脑使用自己的本地数据目录。目录应允许当前 Windows 用户写入；无法写入时程序会明确失败，数据不会回退到 AppData。

## 保存登录状态与升级

登录成功后默认保存登录状态，不需要额外勾选。凭据使用 Windows DPAPI 加密，保存在客户端数据目录的 session.dpapi 中；公开配置 ui.json 不保存密码或令牌。关闭到托盘、真正退出或重启电脑都不会注销，重新启动后自动恢复登录并继续同步。点击配置窗口的「注销」才会清除本机登录凭据，本机消息和附件仍保留。

升级时保留原数据目录：可以将新程序和 DLL 更新到原程序目录，保留 Data；也可以让新程序继续使用原快捷方式指定的 --ui-root 目录。直接把新包解压到另一目录启动，默认会使用新位置的 Data\Drop，因此会被视为新的客户端。不要把 session.dpapi 复制到另一台电脑或其他 Windows 用户下使用，各设备分别登录。

当前服务器的登录凭据有效期为 30 天。凭据到期、账号停用或管理员撤销设备后，需要重新登录；网络暂时断开不会清除已保存的登录状态。

本次 1.0.2 增加消息删除，客户端数据库由 schema 4 自动升级为 5，升级前保存完整本机回退快照。服务器及全部客户端都需要更新到本次构建；旧客户端无法同步删除已有缓存。新客户端连接此前的服务器时仍可正常收发，但「删除消息」禁用。已升级的数据库不能直接交给旧程序使用。

## 界面与缩放

服务器地址、可选私有 CA、账号及本次登录密码放在独立配置窗口。点击「保存配置」保留公开连接选项；地址或账号的修改在下一次登录时使用，不会立即切换已有会话。通知、自启动和压缩选项修改后自动保存。密码不会写入公开设置，登录提交、关闭配置或返回消息时会清除密码框。

主窗口使用传统 Win32 菜单、工具栏和左右分栏，分隔条可拖动，背景与账户区采用蓝灰配色，内容区使用白底。左侧自己置顶，列出本机已有消息的用户和明确查找过的账号，不再提供「全部消息」。在左上角输入完整登录账号并点击「查找账号」，验证成功后进入该用户的消息；在线时自动同步自己、历史参与者和已验证联系人的显示名；未知名称先显示账号 ID，连接恢复后补齐。改显示名后列表、会话标题和历史消息发送者自动更新，登录名保持原样；删除或停用的身份有状态标记并禁止向原身份发送。

发送对象始终跟随左侧选中的账户，输入区上方会明确显示对方名字和登录名；选中自己时显示「发送到：我的设备（自己）」且按钮变为「发给自己」。启动或重新登录后默认选中自己。切换账户后需等该账户视图加载完成才能发送，避免查看对方消息却误发到自己的设备。

通过「添加附件」、将文件拖入输入框，或在文件管理器中复制文件后于输入框按 Ctrl+V，均会在正文输入框上方显示「待发送附件」列表，包括文件类型图标、原始文件名、大小及数量。添加文件不会替换已输入的正文，重复路径不会重复添加，目录不会成为附件；每条消息最多 32 个附件。选中文件后点击「移除所选」或按 Delete 可逐个移除，「清空附件」移除全部。普通文字粘贴保持原有行为；附件预览随窗口 DPI 重新建立，不缩放整张界面截图。

右侧每条消息上方显示发送者及时间，正文下直接列出全部附件名称、大小和「已缓存到本机／待下载」状态。点击附件名字，下方表格会选中对应文件；点击「导出所选附件」后选择保存位置，尚未完整保存的文件不能导出。长正文有提示，选中后可在下方立即阅读全部内容，消息和正文支持文字选择与复制。稳定的用户列表只更新变化的行和未读计数；阅读不禁用用户列表，状态标题改变或新消息到达时保留对应正文的文字选择。

## 附件缓存与已读

客户端收到消息后自动下载附件，逐块保存进度，完整长度和 SHA-256 校验通过后才显示「已缓存到本机」。默认位置为程序旁的 Data\Drop\服务器ID\账号ID\files\附件ID.file；使用 --ui-root 时以指定的数据目录为根。附件内容是独立文件，client.db 记录文件名、大小、摘要、关联消息、下载进度和状态。中央服务器仍保留原附件及消息。

内部缓存文件名是 32 位十六进制随机附件 ID，加 .file 扩展名，例如 0123456789abcdef0123456789abcdef.file；下载中为同一 ID 的 .part。原始文件名仅保存在数据库元信息中，因此按原始文件名或原始扩展名在 Everything 搜索不到缓存。可以在实际客户端数据根目录下搜索 *.file，或使用「导出所选附件」按默认的原始文件名另存为。若由 Setup-Drop.ps1 指定数据根目录，实际 --ui-root 是其 client 子目录；已下载附件位于该目录下的服务器ID\账号ID\files，而非根目录第一层。这是 1.0.1 已有机制，1.0.2 沿用，以避免同名附件覆盖和外部文件名参与内部路径。

「导出所选附件」即另存为：从本机缓存复制到你明确选择的位置，并再次校验；不会为此次另存为重新下载，也不会移走缓存。已经完成缓存的附件可在服务器离线时导出。本机正文和附件默认按 Windows 目录权限保护，登录凭据另由 DPAPI 加密；服务器数据库和附件使用原有存储加密。

中央服务器按账号、会话保存只向前推进的已读位置，发送方及同账号其他设备通过状态通知同步。本机数据库缓存已读状态、设备自己的未读提醒和待提交的阅读意图；断网时保留阅读意图，恢复连接后提交。正文/附件已缓存不代表已经阅读，另存为也不代表对方阅读。新客户端优先提交已读和拉取状态，正在进行的附件请求完成当前块后让出线程，再继续余下传输。

主窗口与配置窗口分别使用逐屏 DPI 和原生字体，按 125%、150%、175% 等比例重新布局。小屏幕下通过右侧滚动条访问底部操作，无需修改 Windows 缩放；跨真实物理屏幕移动仍需在部署环境观察。

## 日常使用

### 删除消息

选中自己账号发送的消息，点击工具栏「删除消息」，或使用消息右键菜单、在消息区按 Delete，确认后删除。权限按发送账号判断：电脑 A 和电脑 B 登录同一账号时，B 可以删除 A 发出的消息；接收账号及其他账号不能删除。发给自己的消息同样支持删除。尚未提交到服务器或恢复后尚未核对的消息不能使用此操作。

删除同步到中央服务器、会话双方账号的所有设备。断网时消息先在当前设备隐藏，状态栏显示「待删除」，任务在真正退出、重启后继续保留；服务器确认后其他在线设备同步移除，离线设备重连时补齐。执行删除无需停止服务。

服务器确认删除后，客户端清除正文、附件下载记录和受管理缓存；缓存文件被占用时保留回收任务并重试。不会删除发送者的原始文件、用户已经导出的文件或以前的备份。服务器取消附件引用，未引用密文按既有宽限期与备份引用规则清理；删除消息不代表历史备份立即清除。

登录后，在左侧选择自己可向自己的其他设备发送文字或附件；选择其他账户可发送给对方。尚未在列表中的账号可先通过「查找账号」验证并选中。发送前核对输入区上方的对象提示。关闭窗口或最小化后留在托盘，真正退出会停止同步，重新启动后补齐历史。

窗口显示时收到新消息会提示任务栏图标；隐藏到托盘后可显示 Windows 通知。“Windows 通知”和“托盘图标闪烁”可在「配置与账号」中分别设置。

1.0.2 的客户端交互、非整数缩放及发布包验证，以及先前 1.0.1 的功能回归范围见项目验收记录；跨物理电脑和长时间运行仍需在实际部署环境观察。
